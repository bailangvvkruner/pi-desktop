# ZCode 对照与体验改进

2026-09-28，基于本地 `reference/zcode` 源码实现。

## 字体区别

两边采用系统 Sans 字体栈，Windows 西文字体通常是 Segoe UI，中文由系统字体回退。ZCode 默认 UI 字号为 14px；我们此前默认 13px，会话列表另降到 12px。上一轮已提升字号，但正文颜色与多处常规字重仍未改变。

ZCode 有多种主题：普通深色主题正文用 neutral-200（约 `#e5e5e5`），ZAI 深色主题用 neutral-300（约 `#d4d4d4`）。本项目此前沿用了后一种配色。因此字体家族相近并不意味着实际观感一样。源码也没有表明 ZCode 全文使用粗体，不能将主观亮度差完全归因于字重。

本次默认 UI 保持 14px，常规界面文字与会话标题采用 500 字重，正文提升为 `#e5e5e5`，辅助文字为 `#b8b8b8` / `#999999`。代码保留独立字号与常规字重，中文等宽回退增加微软雅黑 UI / 微软雅黑 / 苹方 / Noto CJK。旧默认配色自动迁移，明确的自定义配色和手动字号保留。

## 会话耗时口径

耗时只在本机诊断日志记录，导航目标的工作区路径、会话路径和会话 ID 仅用于本地匹配，不写入日志。一次成功记录要求目标会话已提供快照、导航已完成、对应画面已提交并经过绘制机会；取消目录选择、未找到驻留会话和被后续导航替代均记录 `cancelled`。

`cold` 表示后端新建或从文件恢复会话实例；`warm` 来自后端激活已有实例的 `ready` 事件，或重复选择当前已显示的同一会话且无需重新加载。之前访问过但已被释放的实例重新打开仍记为 `cold`，没有快照的取消操作不猜测温度。

`rpcMs` 与 `snapshotMs` 均相对导航开始计时；`renderMs` 是快照到 React 提交的等待时间，包含排队及导航后续刷新，并非纯 React CPU 耗时；`paintMs` 是提交到双动画帧回调的时间，表示获得绘制机会，不是操作系统合成器的精确显示时间。诊断编号与这些阶段元数据会保留在导出的日志中，用于比较冷恢复和驻留切换。

## 会话顶部栏

多会话分屏已按用户要求撤回：删除左右分屏、上下分屏、单窗格恢复、窗格选择和比例调整功能，旧窗口保存的分屏布局不再读取。

主界面恢复为完整宽度的单个聊天区域。会话顶部栏直接位于窗口顶部，保留标题、历史导航、工作台入口及窗口按钮；会话局部错误恢复仍然有效。普通会话与空白新会话使用同一顶部布局。

Office 内容预览的适用范围与限额见 [工作台阅读与文档预览](./workbench-reading-and-office.md)。复杂分页、图片和图表仍由默认应用查看。审批扩展的授权兑现要求见 [局部错误恢复与结构化审批](./error-recovery-and-approvals.md)。

## 验证

初次实现时 `pnpm typecheck`、`pnpm build` 和完整 `pnpm test` 通过；当时 808 项测试中 806 项通过、2 项跳过。撤回分屏后，专属布局测试已删除，界面场景改为检查普通会话和空白新会话的顶部栏位置、窗口按钮对齐、完整宽度以及旧分屏布局不再恢复。

0.1.13 发布前，撤回分屏后的类型检查、构建与完整测试通过，共享驻留会话身份隔离测试迁移后单独验证通过。顶部栏场景的 13 项断言、新建会话的 35 项断言及输入队列的 67 项界面断言通过，截图已检查，测试浏览器已关闭。

隔离的无界面 Chromium 验证覆盖深浅色、900px 窄窗口、终端焦点与模态快捷键、队列逐行等待、工作区状态恢复、词级 Diff、DOCX/XLSX、审批及局部错误恢复。字体实测为 14px / 500，深色正文为 `rgb(229, 229, 229)`。测试使用模拟数据，截图与耗时用于验证实现，不代表真实项目的性能基准；测试浏览器均在结束时清理关闭。
