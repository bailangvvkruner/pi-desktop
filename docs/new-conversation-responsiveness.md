# 新建对话响应与 ZCode 对照

2026-09-28，基于本地 `reference/zcode` 源码审查。

## 原因

0.1.11 的普通 `newSession()` 先等待主进程创建目录、切换工作台、准备 Pi 运行时，再等待工作区与会话列表刷新。期间 `navigationPending` 使输入框不可编辑，并显示“正在连接 Pi”。已有的本地可编辑草稿仅接入了“移除项目关联”，普通新建没有复用它。侧栏与命令面板部分入口还会等整个操作结束才切回聊天。

这个提示并不表示每次都要重新连接远程模型。一次隔离的空配置、无网络运行时测量中，首个实例约 120ms，后续 14 个约 43–52ms；首次模块导入另需约 2.2s。该测量不含完整桌面 IPC、用户扩展与真实项目，不能视为用户机器的端到端成绩。真实初始化还可能等待工作台命令停止、扩展加载或缺失资源安装。

## ZCode 的做法

| 机制 | 源码位置 |
|---|---|
| `startDraft` 同步清除当前任务、展示草稿并递增焦点版本，无需等创建 RPC | `packages/ui/src/store/zcodeSessionStoreWorkspaceSlice.ts` |
| 只有已有 `sessionId` 的视图进入连接状态；草稿有独立的发送入口 | `packages/ui/src/v4/SessionPane.tsx`、`ConversationComposer.tsx` |
| 草稿显示期间后台创建会话，首发使用预热的会话并在确认后正式绑定 | `packages/ui/src/v4/composer/useDraftSessionPrewarm.ts`、`SessionPane.tsx` |
| 以连接、工作区和窗格为单位合并预热；区分已绑定与未绑定会话，处理离开页面和迟到回执 | `packages/ui/src/v4/composer/useDraftSessionPrewarm.ts` |

核心是把“能开始输入”和“运行时已经可发送”分开。Pi 的扩展与工作区运行时带有会话状态，不能为了预热而跨项目共享可变实例。

## 本项目修复

- 普通新建、项目新建、命令面板、快捷键和原生菜单都立即进入独立可编辑草稿并聚焦；Pi 在后台准备。
- 第一条消息可以先提交到本地等待。收到主进程激活完成回执后，才携带真实会话身份发送一次；准备期间停止或切走会取消待发。
- 同目标连续点击合并为同一次准备；侧栏刷新不再阻塞输入或等待中的首发。
- 新建失败保留文字和附件，重试复用原草稿及项目目标。已离开的失败草稿在当前桥接生命周期内可通过同目标“新建”恢复；未成功创建的临时草稿不承诺跨应用重启恢复。
- 主进程在串行激活队列内返回并登记实际草稿作用域。准备期间切走后，输入仍会转存到创建出的会话，不修改当前编辑页、不自动发送。
- 图片、PDF 和上下文读取的进行中任务随草稿作用域迁移，避免初始化完成后附件写回旧临时作用域。
- 新建失败由输入框统一显示与重试，避免重试成功后旧错误通知仍残留。

## 验证

单元与 IPC 回归覆盖即时草稿、草稿隔离、重复点击、激活回执与事件乱序、失败重试、取消首发、迟到作用域转存和未授权作用域拒绝。隔离 Chromium 场景人为延迟准备 RPC，验证所有新建入口、焦点、草稿恢复与跨激活的图片粘贴，并输出截图；它验证交互行为，不作为真实项目性能基准。

0.1.12 发布前 `pnpm typecheck`、`pnpm build` 通过；完整测试 824 项中 822 项通过、2 项跳过。新建界面场景的 35 项断言以及移除项目关联的界面回归通过，截图检查和测试浏览器清理完成。

后台初始化仍需要时间；本次消除的是它对新建页面和打字的阻塞。完整会话冷恢复、扩展耗时和工作台停止命令可依据本机诊断进一步定位。
